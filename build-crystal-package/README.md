# build-crystal-package

Build the workspace FFI crate the Crystal shard links against and run a
`crystal build` smoke check. Crystal shards publish via Git tag tarballs, so
this action verifies that the FFI artifact and the generated bindings are
healthy rather than producing an upload artifact.

## Usage

```yaml
- uses: actions/checkout@v4
- uses: xberg-io/actions/setup-rust@v1
- uses: xberg-io/actions/build-crystal-package@v1
  id: crystal_build
  with:
    ffi-crate: xberg-ffi
    package-dir: packages/crystal
- run: echo "FFI lib at ${{ steps.crystal_build.outputs.ffi-library-path }}"
```

## Inputs

| Name | Required | Default | Description |
|---|---|---|---|
| `ffi-crate` | no | `xberg-ffi` | Workspace FFI crate the shard links against. |
| `package-dir` | no | `packages/crystal` | Directory containing `shard.yml` and the generated bindings. |
| `build-profile` | no | `release` | Cargo profile for the FFI crate (`release`, `dev`, or custom). |
| `setup-crystal` | no | `true` | Install Crystal via `crystal-lang/install-crystal`. |
| `crystal-version` | no | `latest` | Crystal version, passed to `crystal-lang/install-crystal`. |
| `dry-run` | no | `false` | Print the planned commands and exit without building. |

## Outputs

| Name | Description |
|---|---|
| `ffi-library-path` | Absolute path to the built FFI library that the shard links against. |

## Notes

- The action assumes the caller already ran `actions/checkout` and a Rust
  toolchain action (e.g. `xberg-io/actions/setup-rust@v1`).
- After `cargo build` succeeds, the shared library is staged into
  `packages/crystal/native/` where the generated bindings' `@[Link(ldflags:
  "-L #{__DIR__}/../native …")]` resolves it, then the declared shard target
  (`targets.*.main` in `shard.yml`) is built with `crystal build`. A bare
  `--link-flags -L` is also passed so shards generated by older alef versions
  (whose ldflags are just `-l<name>`) link too. If `spec/` exists, `shards
  spec` runs after the build.
- The FFI library name follows Cargo's convention: dashes in the crate
  name become underscores (`xberg-ffi` -> `libxberg_ffi.{so,dylib}`,
  `xberg_ffi.dll`).
- `dev`/`debug` profiles map to `target/debug/`; everything else maps to
  `target/<profile>/`.
- Crystal packages always ship a `--release` build; a `debug` FFI artifact is
  never staged. Publication still happens via the release tag + `shards`
  flow; this action does not upload anything.
